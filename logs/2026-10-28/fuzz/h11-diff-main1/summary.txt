rule unsolicited-101: the machine treats a 101 nobody asked for as final; the exchange core refuses it
rule data-after-close: h11 rejects bytes after a response it will not reuse the connection for; the machine leaves them unread, and a pool must not reuse a connection with bytes left over
rule http10-keep-alive: h11 never reuses an HTTP/1.0 connection; RFC 9112 section 9.3 allows it with keep-alive
rule malformed-connection: a Connection value that is not a list of tokens turns the machine's reuse off; h11 ignores it (the machine is the safer one)
rule bws-before-chunk-extension: h11 rejects whitespace between a chunk size and ';', which RFC 9112 section 7.1.1 allows (BWS); the machine accepts it
rule interim-disables-reuse: the machine's keep-alive only ever turns off, so an interim response that is HTTP/1.0 or carries Connection: close stops reuse even if the final response allows it (safe, not optimal)
