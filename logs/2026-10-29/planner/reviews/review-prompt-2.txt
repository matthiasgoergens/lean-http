Second round of a read-only review of the theorem statements of a pure per-call planner for an HTTP/1.1 client in Lean 4 (v4.34.1). Read only; do not modify anything. The files are in the current directory: LeanHttp/Call.lean, LeanHttp/Call/Redirect.lean, LeanHttp/Call/RetryAfter.lean, LeanHttp/Call/Proofs.lean (the theorems), LeanHttp/Backoff.lean, LeanHttp/Error.lean, LeanHttp/Exchange.lean, LeanHttp/Client.lean (the current client, which does not use the planner yet), and the planner's paragraph in DESIGN.md (section "Milestone 2", the bullet list after "A **per-call planner**"). All proofs compile with no sorry and only propext, Classical.choice and Quot.sound.

The rules: (1) credential fields (Authorization, Cookie, Proxy-Authorization) never appear on a request to a different origin than the one they were given for, https to http counting as different; (2) the hop count never exceeds the limit and reaching it fails with an error; (3) a request whose method is not idempotent or whose body is not replayable is never retried after any byte may have been written; (4) a localClose failure is never retried; (5) every planned delay is within [0, remaining deadline] and within the backoff cap (or the Retry-After limit); (6) a followed 303 yields GET, or HEAD for HEAD; (7) a method-changing redirect carries no body and no content headers.

What was concluded about the first round of review:
- Fixed: plan_no_resend covered only retries, so a 307/308 follow could in principle resend a streamed body: added plan_follow_replayable. Nothing tied the target URI to Hop.origin: added Reachable.target (with uriOrigin_targetUri). Rule 7 held only on the hop where the method changed: added Reachable.emptyBody for every later hop. The 429/503 opt-in and followRedirects off had no theorem: added plan_retry_status and plan_no_follow. "Retries never cross a redirect" lacked its redirect half: added plan_follow_new_hop. Docstrings rewritten where they claimed more than the statement: Reachable.credentials (https to http is now backed by originKey_ne_of_scheme and originKey_ne_of_port), plan_retry_same_hop, Reachable.given, plan_follow_host. Clock.wallSec no longer defaults to 0.
- Kept by design, with the reason: a 3xx at the hop limit that would not be followed anyway (no Location, a streamed body on 307) is delivered, since it is the answer; plan_hop_limit is about redirects that would be followed. Host may be absent from a next request (none on the first request, Connection naming Host, a host that cannot be a field value): the client writes Host from the target when absent (Client.plan), and Reachable.target ties the target to the origin. A Retry-After HTTP-date is measured from the response's Date, to avoid client/server clock skew, and is capped by maxRetryAfterMs and the deadline. A 307/308 answer to a POST is followed with the same method and body: that is a redirect the server asked for, not a retry; the module documentation now says so.
- Refuted: header names are lower case by construction in Std.Http (Header.Name carries an IsLowerCase proof), so a differently cased Authorization cannot slip past credentialNames. URI.port returns the scheme's default when the port is omitted, so start and resolveOrigin agree on default ports.
- Out of scope (reported, not changed here): stale docstrings in Error.lean about localClose and Cause.isConnect; another change is rewriting the client and those docs.
